# Mobile apps (customer and staff) — connecting to a tenant

Both Expo apps (`src/frontend/mobile/customer`, `src/frontend/mobile/staff`) talk to the platform through the API Gateway.
**The Gateway decides the tenant from the host of the request** (CLAUDE.md, "Tenant = request host"): `<code>.shop.erp.local`
for a shop's storefront, `<code>.erp.local` for its back office, a registered custom domain, or the platform host.

## Setting the address

1. Copy `.env.example` to `.env` in the app folder.
2. Set `EXPO_PUBLIC_API_URL` to the tenant's host **with `/api`**, e.g. `http://glcheck.shop.erp.local/api` (customer app) or
   `http://glcheck.erp.local/api` (staff app). In production this is the shop's real domain, `https://shop.example.com/api`.
3. Restart Expo with a cleared cache (`npx expo start -c`) — `EXPO_PUBLIC_*` values are inlined when the bundle is built.

## Why `localhost` does not work

The default (`http://localhost:5000/api`) is only a placeholder: `localhost` is the host of no tenant, so the Gateway refuses
sign-in, ordering and payment calls. The apps print a console warning when the variable is missing.

## On a phone or an emulator

- The phone must resolve the tenant host to the computer running Docker. Android emulator: `10.0.2.2` is the host machine, but the
  `Host` header must still be the tenant's host — easiest is to map the tenant host to the computer's LAN address in the router's DNS
  (or the phone's hosts file) and use that host name in `EXPO_PUBLIC_API_URL`.
- Payment gateways (MoMo, ZaloPay, VNPay) return the customer to `Payment:PublicBaseUrl` / the request host. For a real end-to-end test
  with a provider's sandbox the stack must be reachable from the internet (tunnel) — see `docs/business/Payment/OnlinePayments.md`.

## Real phone test: build, network, data (R68, 2026-11-03)

Runbook for the owner (Vietnamese): [docs/user-guides/mobile-device-test.md](../user-guides/mobile-device-test.md); kit: `deployment/docker/lan-test/`.
- **Identity:** `app.json` has `com.erp.shop` / `com.erp.staff` (placeholders: change them before the first build you may ever publish), icon, adaptive icon, splash (generated by `docs/frontend/design-system/tools/make-app-icons.js`; replace the PNGs with the real logo), `userInterfaceStyle: light` (`expo-system-ui`).
- **EAS:** `eas.json` per app: `preview` = internal APK (`APP_VARIANT=preview`, `EXPO_PUBLIC_API_URL=http://shop.glcheck.lan/api`), `production` = app bundle, HTTPS only. `npm run build:android:preview`. The owner logs in (`npx eas-cli login`) and runs `eas init` once (writes `extra.eas.projectId` into `app.json`).
- **Cleartext HTTP:** `app.config.js` adds `expo-build-properties` `usesCleartextTraffic` unless `APP_VARIANT=production`; checked with `expo prebuild` (the generated `android/` is git-ignored).
- **Permissions:** staff gets CAMERA only (`recordAudioAndroid: false`); the customer app asks for nothing beyond INTERNET.
- **Network:** one custom tenant host (`shop.glcheck.lan`, `TenantDomains` row) serves both apps; do not use `*.local` (Android mDNS); the PC needs inbound TCP 80 (Private profile) and a router DNS record. The local docker-compose has `Tenancy__FallbackTenantCode=SYSTEM`: an unknown host answers as the platform tenant, not 404 - compare data, never trust a bare 200.
- **Status:** configured and verified without a phone (`expo config`, `prebuild`, Jest, LAN check from this PC). The device run is pending the owner's report; R68 stays open until then.

## Local APK build and emulator run (R68, 2026-11-03)

Guide (Vietnamese): [docs/user-guides/mobile-apk-emulator.md](../user-guides/mobile-apk-emulator.md); scripts in `src/frontend/mobile/tools/` (`setup-android-sdk.ps1`, `build-apk-local.ps1`, `start-emulator.ps1`, `android-env.ps1`).
- `eas build --local` does not run on Windows: the local route is `expo prebuild` + `gradlew assembleRelease` on a copy of the app in a short path (`D:/b/<app>`, the 260-character limit breaks CMake), JDK 17 + Android SDK under `D:/Android` (portable, nothing set machine-wide). Output `src/frontend/mobile/apk/<app>-preview.apk` (git-ignored), debug-signed, cleartext HTTP, API `http://shop.glcheck.lan/api`.
- **Permissions:** the merged manifest of a release APK also carries `RECORD_AUDIO`, storage and `SYSTEM_ALERT_WINDOW` (from the Expo template and expo-camera); `android.blockedPermissions` in both `app.json` removes them. Read the merged manifest (`aapt dump badging`), not only `expo prebuild`'s: the earlier "CAMERA only" statement was about the source manifest.
- **Emulator reaches the stack** at `10.0.2.2`; the shop is chosen by the Host, so the Google-APIs image gets `10.0.2.2 shop.glcheck.lan` in its own `/system/etc/hosts` (`-writable-system`, `adb root`, `adb remount`).
- Verified on a Pixel 6 / Android 14 emulator: both APKs install and open; staff sign-in reaches the Dashboard (nginx logs `POST /api/v1/auth/login 200` from okhttp); POS "Scan a barcode" shows the system camera dialog ("Allow ERP Staff to take pictures and record video?"), allowing it grants CAMERA and the preview shows. Not verified: a real scan (the emulator camera is a virtual room), a sale, TalkBack, a real phone.
