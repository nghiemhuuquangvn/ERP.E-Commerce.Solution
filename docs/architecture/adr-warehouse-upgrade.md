# ADR - Warehouse upgrade for Manufacturing (decimal quantities, stock per warehouse and lot)

**Status:** proposed, waiting for the owner's OK on this text (W0, 2026-11-09). **Decided by the owner (2026-11-09):** a new `StockBalance` table next to `Inventory`; all Warehouse quantities become decimal. **Why now:** Manufacturing Phase 3+ (issue, return, receipt, backflush, QC hold, genealogy) needs stock per (item, warehouse, lot) in decimals, production movements and an idempotent write API (`docs/business/M/01_PRODUCTION_BA_SPEC.md` lines ~726-740, 673, NFR-05, BR-MAT-04/06/08; `docs/architecture/adr-manufacturing-service.md` decision 5).

## Where Warehouse stands (explored 2026-11-09)
- `Inventory` is keyed by **ProductId only** (no warehouse). Quantities are `int`; `Cost` is `decimal(18,2)` (weighted average only for `ValuationMethod = Average`). `InventoryLot` has int quantities, lot number, unit cost and expiry but **no** warehouse, status, manufacture date or unique lot number. `StockMovement` has an int quantity and **no cost** (cost lives only on the event). `Reservation` is keyed by `OrderId`.
- No `RowVersion` or lock anywhere; idempotency is a pre-check (`ExistsAsync(product, reference, type)`) without a unique index.
- `MovementType` 0-6; nine handlers create movements. Accounting posts from the event's `ValueDelta` and posts **nothing** for an unknown movement type.
- Internal endpoints: availability (Sales) and warehouse lookup (Manufacturing) only.
- Consumers of int quantities: Product (`Product.StockQuantity`), Purchasing (StockAlert), Sales (client, saga, returned-event mirror), Reporting, POS, Shipping; WH's own PO consumer casts decimals to `int`. No shared contract holds them; each consumer mirrors the event.
- Product has no lot / serial-controlled flags.

## Decisions
1. **`StockBalance`** `(TenantId, ProductId, WarehouseId, LotId?)` with `Quantity`, `ReservedQuantity`, `LockedQuantity` `decimal(18,6)` and a `rowversion`; unique on the key. It is the source of truth for per-warehouse and per-lot questions. **`Inventory` stays the per-item total** that Sales, POS and Replenishment read, so those flows do not change.
2. **One write path.** A new application service `StockLedger` changes `Inventory`, `InventoryLot`, `InventoryLocationStock`, `StockBalance` and writes the `StockMovement` in **one database transaction**. The nine existing handlers move onto it; an architecture test forbids mutating `Inventory` elsewhere. A parity test (sum of balances = inventory total) and `GET inventory/reconciliation` expose drift.
3. **Legacy stock without a warehouse** is assigned from `Location.WarehouseId`, else from the new inventory setting `DefaultWarehouseId`. The backfill report lists tenants where this is ambiguous (several warehouses, locations without warehouse); nothing is guessed silently.
4. **Lots:** `Status` (Available, QcHold, Blocked), `WarehouseId`, `ManufactureDate`, `Source` (Receipt / Production), unique `(TenantId, ProductId, LotNumber)` after a duplicate report. Releasing a hold is a `QcRelease` movement.
5. **Movement types** 7-12: ProductionIssue, ProductionReturn, ProductionReceipt, ProductionScrap, QcRelease, SubcontractTransfer. `StockMovement` persists `WarehouseId`, `LotId`, `UnitCost`, `ValueDelta`; the quantity sign convention is written down once; a filtered unique index `(TenantId, ProductId, Reference, MovementType) WHERE Reference IS NOT NULL` makes idempotency real. **Accounting posts nothing for the new types until Phase 6** (WIP posting keys); the event still carries the value. This gap between stock value and the ledger is a recorded risk.
6. **Decimals:** every quantity `decimal(18,6)`; stored unit costs `decimal(18,6)`, totals 2 decimals. Warehouse does not round quantities (the caller enforces UoM decimals). Events carry decimals. **Rollout order: consumers first** (they read decimals and still accept integers), then Warehouse; an old consumer reading `2.5` into an `int` fails.
7. **Reservations by source:** `SourceType` (SalesOrder default, ProductionOrder), `SourceId`, `WarehouseId`, line `SourceLineId`. Sales keeps `OrderId`, so the order saga is unchanged. Per-line reserve, partial consume, release; `StockBalance.ReservedQuantity` follows.
8. **FEFO suggestion** `SuggestLots(item, warehouse, quantity)`: Available lots, not expired, free quantity above zero, ordered by expiry then received date. The sales reserve uses it too, so expired lots are no longer allocated (documented behaviour change).
9. **Internal write API** `internal/v1/stock/*`, `[AuthorizeInternalService("manufacturing")]`: suggest lots, availability by warehouse / lot, reservations (reserve / consume / release), movements (production types), lots (create, set status). Every write carries an **Idempotency key** (the Manufacturing document number); a repeat returns the first answer. Answers carry the movement id and the **unit cost**. Negative stock is refused unless the call says `allowNegative` (BR-MAT-08). The pending-document and retry pattern on the Manufacturing side belongs to Phase 3.
10. **Product flags** `IsLotControlled`, `IsSerialControlled` (exposed by `internal/v1/product-lookup`); a production receipt without a lot for a lot-controlled item is refused.
11. **Concurrency:** `rowversion` on `Inventory`, `InventoryLot`, `StockBalance`; `StockLedger` retries a conflict three times on a fresh read, then answers 409.

## Milestones
W0 this ADR · W1 decimal quantities end to end (SQL 010, consumers first) · W2 `StockBalance`, lot columns, `StockLedger`, Product flags (SQL 011) · W3 production movement types, persisted cost, unique idempotency index (SQL 012) · W4 reservations by source, partial consume, FEFO suggestion (SQL 013) · W5 internal write API and an MO-A cycle script · W6 DS-01 stock seed, documents, regression of every live script. Each milestone ends with tests, a live check on glcheck, BA documents and a report, and waits for the owner.

## Consequences and risks
Live int -> decimal migration on large tables (lock time, run in a window; every environment needs the script) · consumers deployed out of order break on decimals · two stores (`Inventory`, `StockBalance`) can drift if code bypasses `StockLedger` · legacy stock may be assigned to the wrong warehouse for multi-warehouse tenants · the ledger does not see production movements until Phase 6 · FEFO skipping expired lots changes sales reservations · Warehouse has no integration tests (live scripts stand in) · POS and Storefront keep showing whole numbers · Reporting history keeps its old precision.
